# SIN-605 — PostHog-Key für Lernweg-Ereignisse prüfen und Live-Beleg nachholen

- **Links:** Linear [SIN-605](https://linear.app/sinan-kahraman/issue/SIN-605/posthog-key-fur-lernweg-ereignisse-prufen-und-live-beleg-nachholen); Vorgänger [SIN-387](SIN-387-posthog-laden-nach-einwilligung.md) und [SIN-354](SIN-354-einwilligung-demo-beleg.md); Einwilligungs-Test `e2e/einwilligung-tracking.spec.ts`; Kennzahl-Auslese `scripts/autonomy/posthog.mjs`. Externe Docs (PostHog, Vercel) in diesem Lauf nicht abgerufen, deshalb nicht als Quelle genannt.
- **Entscheidung:** Der Status des Keys in Vercel (Production) wird nicht behauptet. `docs/ENV.md` trägt jetzt „nicht belegt“ mit Begründung. Die Sinan-Aufgabe „Key in Vercel prüfen und ggf. setzen“ ist fertig formuliert (unten), aber noch nicht angelegt. Der Live-Beleg der Einwilligung ist „nicht verfügbar“. `docs/product-readiness.json` bleibt unverändert, weil nichts gemessen wurde.
- **Befund Key (Quelle: Repo):** `docs/ENV.md` führt `NEXT_PUBLIC_POSTHOG_KEY` als „fehlt“. Diese Tabelle beschreibt die Cloud-Agent-Umgebung (Stand 2026-10-03), nicht Vercel. Die Vercel-Liste im selben Dokument nennt den Key nur als optionales Observability-Feld ohne Status. „Fehlt in Vercel“ war in SIN-387 eine Annahme und ist hier nicht belegt.
- **Befund Kennzahl:** Die Kennzahl `posthog` zeigt seit 7 Tagen keine Lernweg-Ereignisse. Die Ursachen sind laut `docs/autonomy/LEHREN.md` (SIN-407) getrennt zu prüfen: Key fehlt oder keine Einwilligung oder kein Verkehr. Ohne Vercel- oder PostHog-Zugriff ist das nicht zu entscheiden.
- **Nicht möglich in diesem Lauf:**
  - Vercel-Abfrage (kein Zugriff auf Umgebungsvariablen).
  - Live-Beleg: `PLAYWRIGHT_BASE_URL=https://content-agent-ashen-nu.vercel.app npx playwright test e2e/einwilligung-tracking.spec.ts` (URL aus `docs/autonomy/config.json`). Der Netzabruf der Live-URL war in diesem Lauf nicht freigegeben. Der lokale Test (SIN-354) ist kein Live-Beleg.
  - `node scripts/autonomy/sinan.mjs create …`: Die Freigabe wurde verweigert. Ohne sie gibt es kein Linear-Issue mit Label `sinan`.
- **Annahmen:** Der Key fehlt in Vercel mit ungewisser Wahrscheinlichkeit. Mit der fehlenden Einwilligung im Test der Kennzahl ist das gleichwertig. Sinan prüft zuerst den Status und setzt den Wert nur, wenn er fehlt.
- **Sinan-Aufgabe (noch anzulegen):**
  - Befehl: `node scripts/autonomy/sinan.mjs create --titel "PostHog-Key in Vercel prüfen und ggf. setzen (NEXT_PUBLIC_POSTHOG_KEY)" --wo "Vercel, Projekt content-agent, Settings → Environment Variables (Production)" --link "https://github.com/siinanXD/Content-Agent-Lernapp/blob/main/docs/ops/SENTRY-POSTHOG.md" --minuten 10 --schritt "1. …" …`
  - Schritte: Vercel öffnen; prüfen, ob `NEXT_PUBLIC_POSTHOG_KEY` für Production gesetzt ist (nur Ja/Nein notieren, Wert nicht kopieren); falls nicht, Project API Key aus PostHog EU eintragen und `NEXT_PUBLIC_POSTHOG_HOST=https://eu.i.posthog.com` setzen; neu deployen, weil `NEXT_PUBLIC_*` beim Build eingebettet wird.
  - Prüfung: Auf der Live-App `/einwilligung` → „Einverstanden“, dann eine Einheit öffnen. In PostHog (EU) erscheint `unit_started`; die Kennzahl `posthog` zeigt wieder Ereignisse.
- **Warum:** Ein Befund darf nur sagen, was gemessen wurde. Die Lücke bleibt sichtbar, bis Vercel oder die Live-App einsehbar sind. Die Sinan-Aufgabe braucht keinen Geheimniswert im Issue.
