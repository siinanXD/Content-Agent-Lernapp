# SIN-295 — CodeQL und automatische Paket-Updates

- **Links:** Linear [SIN-295](https://linear.app/sinan-kahraman/issue/SIN-295); GitHub [CodeQL-Action](https://github.com/github/codeql-action) (MIT), [CodeQL für öffentliche Repos](https://docs.github.com/en/code-security/code-scanning/introduction-to-code-scanning/about-code-scanning-with-codeql), [Dependabot-Optionen (groups, schedule)](https://docs.github.com/en/code-security/dependabot/working-with-dependabot/dependabot-options-reference), [Renovate](https://github.com/renovatebot/renovate) (AGPL-3.0, Dienst als GitHub-App)
- **Entscheidung:**
  1. **Dependabot statt Renovate.** Beide können Wochenbündel und Major einzeln. Dependabot ist in GitHub eingebaut (keine App, kein Token, kein neuer Dienst, eine Datei `.github/dependabot.yml`); Renovate bräuchte eine App oder einen eigenen Lauf und ist AGPL-3.0. Weniger Abhängigkeiten gewinnt. `pr-gate.yml` kennt Dependabot-PRs schon (Titelprüfung übersprungen).
  2. **Updates:** npm und GitHub Actions, montags 06:00 (Berlin). Minor und Patch kommen als ein Bündel je Ökosystem, Major je Paket als eigener PR. Titel `chore(deps): …` / `ci(deps): …`. Die Risiko-Labels setzt weiter nur `pr-gate`: Patch/Minor von Paketen, die schon in `package.json` stehen, sind `risk:medium` und mergen bei grünen Checks; Major-Updates der Framework-Pakete (`next`, `react`, `@supabase/supabase-js`) stuft `risk.mjs` ohnehin hoch ein.
  3. **Sicherheits-Updates sofort:** Das sind Dependabot security updates, sie laufen unabhängig vom Wochenplan. Sie sind eine Repo-Einstellung (Settings → Code security), keine Datei; siehe Annahmen.
  4. **CodeQL** als eigener Workflow `codeql.yml`: bei PR, Push auf `main`, montags 04:17 UTC und von Hand. `javascript-typescript`, `build-mode: none`.
  5. **Hohe Funde blockieren:** `scripts/autonomy/codeql-gate.mjs` liest das SARIF und scheitert ab `security-severity` 7.0 (GitHub-Stufen high und critical). Das SARIF liegt 14 Tage als Artefakt `codeql-sarif`.
- **Annahmen:**
  - **Kein Upload in den Security-Tab.** Der Upload braucht `security-events: write`; das ist nach `risk.mjs` ein erweitertes Recht (`risk:high`). Der Issue verlangt `risk:medium` ohne zusätzliche Rechte. Darum `upload: never` und Auswertung im Workflow (`contents: read`). Preis: keine Funde im Security-Tab und keine Anmerkungen im Diff, nur Fehlerzeilen im Lauf. Mit Freigabe von Sinan lässt sich das später auf `upload: always` mit `security-events: write` umstellen.
  - **Python fehlt noch.** Im Repo liegt keine `.py`-Datei (Hermes-Worker, AP-10, ist noch nicht da); CodeQL bricht ohne Quellcode einer Sprache ab. Sobald Python-Code liegt, kommt `python` in `languages`.
  - **Pflicht-Check:** `analyze` ist nicht im Ruleset als erforderlicher Check eingetragen (Branch-Protection ist das Gate selbst, nur mit Freigabe). Der Merge-Stopp bei hohen Funden greift deshalb erst, wenn Sinan `analyze` als erforderlich einträgt; bis dahin zeigt der Lauf rot.
  - **Sicherheits-Updates einschalten:** Dependabot alerts und security updates müssen in den Repo-Einstellungen aktiv sein (öffentliches Repo: kostenlos). Das ist nicht aus dem Repo heraus setzbar.
  - **Dependabot-PRs haben keinen Zugriff auf Secrets.** `pr-gate` fällt dann auf `github.token` zurück (so im Workflow vorgesehen). Ob der Auto-Merge mit diesem Token greift, zeigt erst der erste Update-PR; sonst Folge-Issue.
  - Der erste Update-PR entsteht montags nach dem Merge; sein Durchlauf ist hier nicht prüfbar.
