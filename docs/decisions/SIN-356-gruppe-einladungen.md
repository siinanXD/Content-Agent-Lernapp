# SIN-356: Gruppe anlegen und Teilnehmende einladen

- **Links:** Linear [SIN-356](https://linear.app/sinan-kahraman/issue/SIN-356), [SIN-307](https://linear.app/sinan-kahraman/issue/SIN-307), [SIN-277](https://linear.app/sinan-kahraman/issue/SIN-277); Supabase [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security), [Database Functions](https://supabase.com/docs/guides/database/functions); Figma [Lern-App](https://www.figma.com/design/0SWGDO2ioBD3MyXiAnrbRz)
- **Entscheidung:** Schreiben bleibt für Nutzer gesperrt (SIN-277). Neu sind zwei `security definer`-Funktionen mit festem `search_path`, die Rolle `ausbilder` und die eigene Gruppe prüfen: `ausbilder_gruppe_anlegen` (eine Gruppe je Ausbilder) und `ausbilder_einladung_erzeugen` (legt den Platz in `group_members` und einen Code in der neuen Tabelle `group_invitations` an, höchstens 100 je Gruppe). Die API-Routen `POST /api/ausbilder/gruppe`, `GET/POST /api/ausbilder/einladungen` laufen mit dem Anon-Key und dem Token der Person, nie mit dem Service-Role-Key. Die Seite `/ausbilder` zeigt ohne Gruppe das Formular „Gruppe anlegen“ und mit Gruppe den Abschnitt „Teilnehmende einladen“. Kein neues Paket.
- **Annahmen:**
  - Figma nicht verfügbar: Zu Formular und Einladungsliste gibt es keinen bekannten Frame (W11 zeigt nur die Aktion). Umgesetzt nur mit vorhandenen Bausteinen (`TextField`, `Button`, `StateView` für Laden, Leer, Fehler nach Screen 17, `bento-tile`). Der Figma-Abgleich bleibt offen; Sinan prüft beim Ansehen.
  - Ein Name je Einladung im Formular. Die API nimmt bis zu 30 Namen auf einmal, damit später ein Mehrfachfeld ohne API-Änderung möglich ist.
  - Der Code (10 Zeichen, gezeigt als `AB12C-34DEF`) ist eine Zufallskennung. Eine Einladung wird nicht versendet: Es gibt keine E-Mail-Adressen (Personendaten); die Ausbilder geben den Code selbst weiter. Das Einlösen eines Codes auf dem Gerät der Lernenden (Code → `anonymous_id`) ist nicht Teil dieses Pakets und braucht ein eigenes Issue; bis dahin steht die Person in der Übersicht als „Noch nicht aktiv“.
  - Namen mit „@“ werden abgelehnt (in Formular, API und Datenbank), damit keine E-Mail-Adressen als Anzeigename landen. Es gehen keine Namen in Prompts.
  - Eine neue Gruppe hat keinen Kurs (`course_id` leer), Fortschritt steht daher bei 0 %. Die Zuordnung zum Kurs bleibt wie in SIN-277 Handarbeit.
  - Die Migration muss auf Supabase laufen. Ohne sie zeigt die Seite den Fehlerzustand mit „Erneut versuchen“. Wegen RLS und Funktionsrechten wird der PR vom Gate als `risk:high` geführt und wartet auf die Freigabe.
- **Warum:** Funktionen in der Datenbank halten die Regeln (Rolle, eine Gruppe, Obergrenze) an einer Stelle, ohne dem Client Schreibrechte oder dem Server den Service-Role-Key zu geben.
