# SIN-415: Mehrere Gruppen, Archiv statt Löschen, Zugang per Einladungslink

- **Links:** Linear [SIN-415](https://linear.app/sinan-kahraman/issue/SIN-415), [SIN-390](https://linear.app/sinan-kahraman/issue/SIN-390), [SIN-356](https://linear.app/sinan-kahraman/issue/SIN-356); Supabase [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security), [Auth Admin `createUser`](https://supabase.com/docs/reference/javascript/auth-admin-createuser), [Passwordless Login](https://supabase.com/docs/guides/auth/auth-email-passwordless); Figma `0SWGDO2ioBD3MyXiAnrbRz`, Frames G0 `82:384`, G5 `82:409`, G6 `82:451`, G7 `82:471`
- **Entscheidung:**
  - **Datenbank (additiv, eine Einschränkung weniger):** Die Eindeutigkeit `trainer_groups.trainer_id` entfällt, damit ein Ausbilder mehrere Gruppen hat. Neu: `trainer_groups.archived_at` und `organisation_id`, Tabellen `organisations` (Kontingent `trainer_quota`, `member_quota`), `organisation_trainers` (Konto → Organisation) und `trainer_access_links` (Einladungslink, einmal einlösbar, optional mit Ablauf). Alle drei sind für Nutzer gesperrt (RLS an, keine Policy); gelesen wird über `security definer`-Funktionen mit festem `search_path`. Es wird nichts gelöscht: Archivieren setzt nur `archived_at`.
  - **Kontingent:** Belegt sind die Mitglieder aller **aktiven** Gruppen der Organisation. Archivieren gibt die Zugänge frei. Einladen und Wiederherstellen prüfen das Kontingent in der Datenbank (Fehlercode `54001`); Wiederherstellen geht nur, wenn alle Mitglieder der Gruppe wieder Platz haben. Ausbilder ohne Organisation (Demo-Zugänge aus SIN-277) haben kein Kontingent und bleiben unverändert nutzbar.
  - **Einladungslink (G0):** `/ausbilder/zugang?code=…`. Die API `/api/ausbilder/zugang` ist die einzige Stelle mit Service-Role-Key (nur serverseitig; die vier Funktionen `zugang_*` sind nur für `service_role` freigegeben). Ablauf: Link atomar reservieren, Konto mit `app_metadata.role = 'ausbilder'` anlegen (nur serverseitig setzbar), Organisation zuordnen, Anmelde-Link per `signInWithOtp` senden. Schlägt das Anlegen fehl, wird der Link wieder freigegeben. Kein Passwort.
  - **Seiten:** `/ausbilder/gruppen` (G5), Bestätigungsdialog (G6, natives `<dialog>`, kein neuer Baustein im Sinn einer Komponentenbibliothek), `/ausbilder/archiv` (G7). Die bestehende Gruppenübersicht `/ausbilder` zeigt mit `?gruppe=<id>` eine bestimmte Gruppe (auch archiviert, dann ohne Einladen); ohne Angabe die einzige aktive, bei mehreren leitet sie zu Meine Gruppen. Der Anmelde-Link führt jetzt nach `/ausbilder/gruppen`.
  - **Einladungen:** `ausbilder_einladung_erzeugen(p_group_id, p_display_name)` ist neu; die alte Form ohne Gruppe bleibt und gilt nur bei genau einer aktiven Gruppe.
- **Annahmen:**
  - SIN-390 (Prüfung der Migration „Gruppe anlegen und einladen“) war beim Start nicht als abgeschlossen erkennbar. Diese Migration baut auf `20261009010000_sin356_…` auf und ersetzt deren Funktion `ausbilder_gruppe_anlegen` per `create or replace`; die RLS-Policies von SIN-277/356 bleiben unverändert.
  - „Azubis sehen die Gruppe nicht mehr“: Heute liest kein Teil der Lern-App Gruppen (das Einlösen des Beitrittscodes auf dem Gerät der Lernenden gehört zu SIN-356 und ist offen). Die Spalte `archived_at` ist dokumentiert (Kommentar in der Datenbank); jede künftige Stelle für Lernende muss `archived_at is null` filtern.
  - Der Admin-Teil (Organisation und Links anlegen) ist ein eigenes Issue. Bis dahin legt Sinan Zeilen per SQL an. Ein Link ist ein Zufallscode mit 12 bis 64 Zeichen `A–Z a–z 0–9 _ -`; es gibt eine Ausbilder-Obergrenze je Organisation (`trainer_quota`), geprüft beim Reservieren.
  - Eine Gruppe mit gleichem Namen (ohne Beachtung der Groß-/Kleinschreibung) gibt es je Ausbilder nur einmal aktiv; archivierte zählen nicht. So bleibt ein doppeltes Anlegen durch Doppelklick folgenlos.
  - Kein Rate-Limit für `/api/ausbilder/zugang`: Der Code ist ein langer Zufallswert, falsche Codes liefern immer dieselbe Antwort. Supabase begrenzt zudem E-Mails je Adresse. Bei Missbrauch nachziehen.
  - Der Anmelde-Link verlangt, dass `/ausbilder/gruppen` in Supabase unter „Redirect URLs“ erlaubt ist (Wildcard für die Domain genügt). Ist nur `/ausbilder` freigegeben, fällt Supabase auf die Site-URL zurück; der Zugang funktioniert trotzdem.
  - Figma-Werte gelesen (Text, Radius 24, Balken 6 px, Tokens `brand/primary` und `brand/accent` für den Balken auf dunkel). Dialog-Hintergrund: Figma zeigt abgeblendete Kachel, umgesetzt als Token-Mischung `--color-bg-hero` 60 %.
  - Vom Gate als `risk:high` geführt (RLS, Auth, Migration mit `drop constraint`); wartet auf `freigegeben`.
- **Warum:** Regeln (Rolle, Besitz, Kontingent, Archivierung) bleiben an einer Stelle in der Datenbank; der Service-Role-Key ist auf die eine Server-Route begrenzt, die ein Konto anlegen muss und das mit Nutzerrechten nicht kann.
